合同审核对话智能体 产品需求文档

在一个对话框里完成经验投喂、知识沉淀、合同审核与持续纠错——不建任何管理页面，结果由 agent 直接产出
文档版本：v2.0（草案，对话形态修订） 日期：2026-10-12 状态：待评审 文档类型：新产品 PRD（重型）

1背景与问题

Evidence → affected user & moment → product decision → observable outcome

观察到的问题：企业合同审核高度依赖法务个人经验——审核原则散落在指引文档、聊天记录和老法务的脑子里；历史合同的审核案例（含修订痕迹与点评）难以复用；新人审合同尺度不一、漏审高发；面对几十页合同逐条排查成本高、效率低。通用大模型虽能"看"合同，但其意见没有企业立场、不引用企业内部标准、无法持续积累组织经验，且存在无依据编造风险，难以在真实审核场景中被信任。

受影响的用户与时刻：法务/合同审核人员在两类时刻最痛：①拿到新合同（或单个争议条款）需要快速给出有依据的审核意见时；②想把自己的审核经验与历史案例传承给团队、沉淀为组织资产时。这两类时刻都发生在即时沟通工具里，用户不愿为了审一份合同去学习和操作一套专门系统。

产品决策：构建一个纯对话形态的合同审核智能体。用户只需在对话框里粘贴条款、上传文件、用自然语言交代"这是原则，学一下""帮我按乙方立场审"，智能体即在对话中完成解析、知识提炼、风险审核与结果产出；所有知识沉淀经用户在对话中确认后生效，审核反馈通过对话中的自然语言纠错回流，形成"投喂—沉淀—审核—反馈"双闭环。产品不提供独立的知识库管理页面、报告页面或任何 Web 控制台；对话是唯一交互界面。

预期可观察结果 ①用户在对话中投喂原则/案例，收到结构化知识候选消息，回复确认后知识即在库中可检索、可被审核引用；②审核新合同时，结果直接出现在对话里，每条风险意见都能看到编号依据并可要求展开出处；③用户对结果说"这条错了/漏了一条"，智能体即生成知识更新候选，确认后再审同类条款口径改变。

2产品目标与非目标

2.1 产品目标

目标可观察的产品表现
纯对话可用用户全部工作（投喂、确认知识、审核、追问、纠错、管库、导出）均在单一对话窗口以自然语言 + 文件附件完成，无需打开任何页面；不熟悉指令的用户说大白话也能完成。
经验可沉淀原则与案例（条款级/合同级）经对话内解析、提炼、确认三步成为生效知识条目，沉淀过程无需用户理解任何技术概念。
知识可进化知识条目支持版本更新、停用、冲突裁决，均可通过对话指令完成；每次变更保留来源与版本链。
审核有依据单条款与整篇合同审核输出的每一条风险发现，均至少引用一条生效知识条目（规则或案例）；无依据的内容只能以"待确认提示"形式出现，不得冒充风险结论。
尺度可配置审核立场（甲方/乙方）、合同类型与严格度均可在对话中口头设定并可记住为默认，单次可临时覆盖；同一合同在不同立场下输出不同意见。
结论可信任风险分级、置信度、依据编号与展开、缺失/未覆盖显式声明、人工终审提示贯穿全部对话产出；整篇报告永久绑定出审时的知识库版本快照。

2.2 非目标（P0 明确不做）

  • 不做任何 Web 管理界面/控制台：不建知识库管理页、审核任务列表页、报告详情页、设置页。全部能力通过对话与对话内结构化消息承载。
  • 不做无人值守的自动决策：智能体不出具最终法律意见、不自动拒签/放行合同；所有风险结论为辅助意见，需人工终审。
  • 不做黑盒模型再训练：用户素材不通过不可见的"模型微调"消化；所有可用于审核的知识必须以人可读、可编辑、可停用的条目形式存在并经确认生效。
  • 不做合同起草/在线编辑/电子签：P0 仅提供条款级修改建议文本（直接在对话中给出，可复制；整篇可按用户要求导出为文件），不做合同起草、在线修订、签署流程。
  • 不做外部法规自动更新库：法律法规等外部权威来源的自动订阅列入 P1；P0 外部法规只能由用户在对话中投喂。
  • 不做审批流替代与多人协作权限体系：P0 面向单工作空间内的对话使用，不内置多级法务审批/用印流程与角色矩阵。

3用户与核心场景

3.1 目标用户

主要用户 · 企业法务 / 合同管理员 经验沉淀者 & 审核执行者

手头有审核指引、历史合同修订稿和自己总结的套路。希望像跟助理说话一样把材料丢过去沉淀经验，并对业务部门发来的新合同快速拿到可发出的审核意见。

次要用户 · 业务经办（采购/销售/BD） 前置自查者

合同法务终审前，把争议条款或合同初稿直接发到对话框做前置自查。只使用审核能力，不沉淀知识（P0 不做权限隔离，仅通过约定使用方式区分）。

次要用户 · 法务负责人 / 外部律师 标准制定者 & 复核者

投喂审核原则与风险偏好，在对话中裁决规则冲突、追问高风险合同的依据与让步底线，关注知识库质量与审核口径一致性。

3.2 核心场景（全部发生在对话中）

场景用户在对话框里做什么完成证据（agent 的产出）
S1把审核指引/历史合同修订稿作为附件发出，或直接粘贴条款案例并说"学一下"agent 回复知识候选消息，用户逐条确认后，回复"已生效"并可被后续审核引用
S2粘贴一句争议条款（可带一句"按我方是供货方看"）agent 回复单条款审核卡：风险等级、依据编号、修改示范；可继续多轮追问
S3上传整篇合同文件（Word/PDF），说"帮我审，甲方立场"agent 流式汇报进度后回复总体结论 + 逐条发现 + 缺失/一致性问题；用户可要求导出 Word/PDF
S4直接回复审核结果："第 2 条误报""漏了数据合规的问题，以后这类要提示"agent 记录反馈并生成知识更新候选，确认后入库，再审同类条款口径改变

4产品形态与核心机制

一个对话框 · 三层知识库 · 人在回路的知识沉淀 · 依据可溯源的合同审核

4.1 产品形态：对话即产品

  • 单一对话窗口：用户面向的就是一个聊天窗口（承载终端不限：独立对话应用 / 企业 IM 内的机器人会话 / 网页聊天窗，P0 至少落地一种，终端选择见 Q1）。窗口支持文本输入与文件附件（.docx / 文字版 .pdf / .txt）。
  • 无页面跳转：知识库、审核任务、报告均不是"页面"，而是对话中的消息（结构化卡片消息 / 文本结论 / 文件消息）；查库、改规则、停用条目均通过对话指令完成。
  • 自然语言优先，快捷操作辅助：卡片消息上可附快捷操作（如"✅确认 / ✏️修改 / 🔀合并 / ❌驳回"），但每一项操作都必须能用纯文字完成（如回复"第 2 条改成日万分之三""驳回第 3 条"），保证用户只用打字也能完成全部工作。
  • 跨会话记忆：会话可以关闭重开；知识库、审核配置（默认立场/严格度）跨会话持久保留；单个合同的审核上下文在该会话及历史消息中可随时找回。

4.2 三层知识模型

知识库不是一个"文档堆"，而是由三层结构化知识构成。审核时三层协同：原则层定立场与裁决优先级，规则层做结构化判定，案例层做语义比对与佐证。三层均由对话投喂、对话确认、对话管理。

第一层原则层 · Principle

审核立场与总纲。例："我方作为供货方，不接受无限连带责任""违约金不超过合同总额 20%""争议管辖优先约定我方所在地法院"。来源：公司审核指引、风险偏好表述。作用：立场过滤、规则冲突时的裁决依据、规则未覆盖时的兜底参照。

▲ 约束 / 裁决
第二层规则层 · Rule（审核主力）

按条款类型沉淀的可执行审核标准：适用合同类型、适用立场、风险点、判定条件（可含量化阈值与正反模式）、风险等级、建议修改文本。每条规则带稳定 ID、版本与来源。审核时优先进行结构化判定。

▲ 支撑 / 佐证
第三层案例层 · Case

真实的问题条款（反例）、优质条款（正例）、整篇历史合同及专家点评/修订记录。审核时对表述各异的新条款做语义相似度匹配，提供"历史上怎么判、怎么改"的实例佐证，也是生成修改示范的素材。

4.3 核心机制一：人在回路（Human-in-the-loop）的知识沉淀

智能体对投喂素材做解析与提炼，在对话中产出知识条目候选消息；候选必须经用户在对话中确认/编辑后才能"生效"参与审核。系统永不自动生效规则、永不因投喂直接改写已生效规则。这是法律场景下产品可信的底线机制。

4.4 核心机制二：双闭环

闭环 A · 学习闭环（对话投喂 → 知识库）

1对话投喂发附件/粘贴文本，说"学一下，这是原则"
→
2对话确认解析agent 汇报切分与归类，用户口头纠正
→
3候选消息结构化卡片逐条发出，自动标重/标冲突
→
4对话确认"通过/改成…/和 R-014 合并/驳回"
→
5生效入库agent 回执生效 ID，立即可引用

闭环 B · 审核闭环（新合同 → 对话纠错 → 回流知识库）

1提交合同发条款文本或合同文件，口头设定立场
→
2检索比对规则判定 + 案例匹配 + 原则立场约束
→
3对话产出分级、依据编号、修改建议、置信度
→
4口头处置"采纳/驳回/接受风险/第2条改成…"
→
5反馈回流生成更新候选，确认后回到闭环 A
↺ 高频同类驳回时，agent 主动在对话中提示"是否把这个模式沉淀为规则修订"，但同样不自动生效
为什么不直接"喂给大模型让它自己学" 黑盒学习无法回答"这条意见依据的是哪条公司标准"，无法停用一条错误经验，也无法保证立场一致。本产品的"学习"= 可审计的知识资产积累：智能体负责提炼与匹配，人负责确认与裁决；模型能力可以替换升级，知识库始终归用户所有。

5对话交互总则

以下规则适用于智能体的全部对话行为，各 FR 不再重复定义

5.1 意图识别与模式自动切换

用户无需选择"学习模式/审核模式"。智能体根据消息内容与附件自动判断意图，并按以下规则处理：

识别意图典型信号智能体行为
投喂学习附件 + "学习/存档/这是我们的标准/原则/指引"；或文本 + "记一下"进入 FR-02 学习流程
请求审核条款文本；合同附件 + "审一下/看看/有没有问题"；无附件时直接粘贴一段条款进入 FR-05/06 审核流程
管理知识库"库里有哪些…""停用…""改成…""回滚…""R-014 是什么"进入 FR-03 管理流程
追问针对上一条审核结果的提问（"换成乙方呢""让步底线"）在当前审核上下文内多轮回答
反馈纠错"不对/误报/漏了/驳回/我改成…"进入 FR-08 反馈流程
歧义处理意图不明（例：发来一份合同但没说学还是审）时，智能体只用一句话+选项确认："这份文件是要我【学习成案例】还是【按新合同审核】？"，不得擅自假定为学习（避免脏知识入库）。

5.2 消息形态规范

消息类型用途规范
普通文本消息结论、说明、追问回答、回执先结论后理由；长内容分段；一次对话只推进一件事
知识候选卡片FR-02 提炼结果一候选一卡：字段结构化、来源锚点摘要、疑似重复/冲突显著标记、附快捷操作；同批卡片编号（候选 1/3…），用户可按编号批量操作
审核发现卡片FR-05/06 审核产出字段遵循 §9.1 规范：定位、等级、原文摘录、问题说明、依据编号、建议文本、置信度；整篇发现统一编号（发现 1/N…）供用户按号引用
进度消息整篇解析/审核长任务先回一条"已收到，开始处理"，随后以编辑同一条消息或短消息汇报阶段进度（解析→审条款 x/N→一致性检查），任务结束给完成回执
确认请求消息高影响操作复述操作内容与影响，明确等待"确认/取消"，未获确认不执行
文件消息整篇审核报告导出仅在用户要求时产出 Word/PDF 文件（FR-07）

5.3 高影响操作确认门槛

以下操作必须由智能体复述影响并取得用户明确确认（"确认/对/执行"）后才执行；快捷操作点选视同明确确认：

  • 知识条目生效、编辑修订已生效条目、停用/启用、回滚版本、冲突裁决；
  • 批量通过候选（需告知数量与冲突项除外）；
  • 删除素材；
  • 导出整篇审核报告（确认导出口径：全量/仅未解决问题）。

普通查询、单条款审核、追问、反馈记录（仅记录、不改知识库）无需确认。

5.4 对话中的依据引用规范

  • 发现卡内用编号角标引用依据，如 12，编号在本报告内对应"依据清单"；用户回复"展开依据 1"或"1 是什么"即收到该条目的完整内容与来源原文摘录。
  • 依据标注一律带条目 ID 与版本（如 R-PAY-014 v3）；无依据内容只能以"待确认提示"样式出现，禁止使用角标伪装。
  • 对话中引用条目内容时，区分"库内原文"与"智能体改写"（库内建议加引号标注来源，自行润色部分不加）。

5.5 其他对话行为规则

  • 无依据不臆造：阈值、法条、公司标准未在知识库中时，明确说"知识库未覆盖"，不得编造；可引导投喂。
  • 可撤销：知识类操作完成回执中固定带"回复'撤销'可回退本次操作"（撤销窗口见 §11.6）；审核任务可随时说"停止"，已产出部分保留。
  • 口径记忆：立场/严格度等配置（FR-04）与待裁决冲突等状态，智能体在相关对话中主动复述当前值，避免用户失忆。
  • 单任务聚焦：长流程（学习确认、整篇审核）中用户临时插话，智能体先处理插话，再用一句话提示未完成事项（"当前还有 3 张候选待确认，需要继续吗？"）。

6范围（P0 / P1）

P0 最小完整旅程：用户首次打开对话 → 智能体引导投喂 1 份原则与 1 个案例并在对话中确认入库 → 用该知识库完成 1 次单条款审核与 1 次整篇合同审核 → 对结果口头纠错并把 1 条反馈沉淀回库。每一步失败都有对话恢复路径（解析失败可重发、提炼不准可口头改、审错了可驳回回流）。

FR-01对话接入与意图识别P0

目的：让用户用最自然的方式（发消息、发文件、说大白话）开始学习或审核，无需模式切换。

触发与输入

  • 文本消息；附件消息，P0 支持 .docx / .pdf（文字版）/ .txt；可引用回复某条历史消息发起追问或纠错。

处理规则

  1. 按 §5.1 识别五类意图（投喂/审核/管理/追问/反馈）；识别置信不足时按"一句话+选项"确认，默认不替用户决定。
  2. 文件先做可解析性预检（加密、损坏、无文字层、格式不支持），不通过即在同一会话明确回复原因与替代办法，不产生后续脏流程。
  3. 识别到长任务（整篇解析/审核）立即回"已收到"回执，再进入处理，避免用户等待无响应。
  4. 引用回复或"第 X 条/发现 X"这类指代，智能体需在当前会话上下文中解析到具体卡片；解析不到时反问确认，不猜。

异常与边界

情形智能体回复行为
扫描件/图片型 PDF"这份 PDF 是扫描件，读不出文字，P0 暂不支持；可发 Word/文字版 PDF"（不得用乱码继续）
意图歧义一句话两选项确认；用户也可直接纠正："学"或"审"
文件超限/超长篇幅告知上限（P0 至少 50 页，具体值 TBD）并建议拆分；不静默截断
指代无法解析列出最近可选项请用户指认
FR-02素材学习与对话确认P0

目的：把对话投喂的非结构化材料转成三层知识条目，并在对话内完成人工确认。

处理规则

  1. 投喂信息：案例类需明确立场；用户未说时智能体补问一次。素材类型可由用户声明（"这是原则"），未声明时按内容推断并在解析回执中说明、允许纠正。
  2. 解析回执消息：正文提取后汇报——识别到 N 个条款、条款类型归类列表、意见配对情况（整篇案例）；用户可口头纠正："第 7 条应该是保密""把 5.2 和 5.3 合并看"。修正后的结果作为提炼输入。
  3. 候选卡片：按素材类型提炼：原则→原则卡；指引→规则卡；案例→案例卡（点评含可复用标准时附规则卡）。字段遵循 §7.2，缺失字段标"待补充"，不得编造阈值与来源；每卡展示来源锚点摘要（文件名+章节+原文摘录一句话）。
  4. 去重：与已生效/候选条目语义高度相似时卡顶标"疑似重复 ↔ R-XXX"，并排差异摘要，提供"合并"指令；合并保留全部来源。
  5. 冲突：同类型同立场下判定互斥的标"冲突待裁决"，冲突卡不允许通过；用户说"以新的为准/以 R-XXX 为准"完成裁决，被取代条目转"已停用（被取代）"并留版本链；原则优先级可作智能体推荐理由，不替用户决定。
  6. 对话操作指令（纯文字必须全部可达）："确认/通过""候选 X 改成：…""X、Y 合并""驳回 X，原因…""全部通过（冲突项除外）""继续"。快捷点选等同指令。

回执与状态变更

每确认一张：回执"R-XXX v1 已生效，可在审核中引用（回复'撤销'回退）"；全部处置完成后素材转"已入库/已忽略"，并汇总本批生效条目数。

硬性信任规则 ①候选不自动生效；②生效条目不被新投喂静默改写，修订必生新版本；③AI 生成字段与用户修改在卡片中视觉可区分，确认责任归用户。

FR-04审核口径配置（对话设定）P0
配置项取值与行为
我方立场甲方/乙方。仅匹配该立场及"双方通用"规则，案例按立场相关性排序。必选：用户说"帮我审"但未给立场时，智能体在审核前补问一次；用户说"以后默认乙方"则记住。
合同类型自动推荐并告知，可口头纠正；用于过滤规则与缺失检查清单。

规则范围"只用买卖合同的规则审"等口头限定；默认全部已生效条目。
两层生效"默认配置"跨会话记忆（"以后都按乙方、标准"）；单次说法仅覆盖当前审核（"这份按甲方看"）；每次审核开头复述本次生效配置供纠正。
FR-05单条款审核对话P0

处理规则

  1. 识别条款类型 → 在当前配置范围内：规则结构化判定（模式 + 阈值换算比较）→ 案例语义匹配 → 原则兜底。
  2. 阈值命中要展示计算过程（如"日千分之一 ≈ 年化 36.5%，超 LPR 4 倍上限"）。
  3. 无规则命中但有相似案例：以案例佐证出意见，置信度不超过"中"。
  4. 未覆盖：无相关生效知识时不做风险定性；回复客观解读 + "知识库未覆盖该类风险，建议人工判断"，并附"要我把这条存成案例吗？"投喂入口。
  5. 多轮追问："换成乙方立场呢""让步底线是什么""给两个语气强弱不同的版本"——追问回答同样受依据约束，无依据显式说明；追问中形成的有效结论可一句话存为反馈/案例。

产出

单条审核发现卡片消息（或无风险时的简短结论）：条款解读 → 发现（等级排序）→ 未覆盖提示 → 可复制的建议文本；附快捷处置（采纳/驳回/存案例）与"展开依据"。

FR-06整篇合同审核对话P0

处理规则

  1. 解析与要素确认：切分条款，抽取合同主体、类型、金额币种、关键期限、签署日；先发一条"要素确认消息"请用户口头纠错，确认（或用户说"直接审"）后开始。
  2. 进度汇报：通过编辑进度消息汇报"已审 x/N 条 → 完整性检查 → 一致性检查"；用户随时可说"停止"，已完成部分保留。
  3. 逐条款审核：每条按 FR-05 同逻辑判定；发现携带章节号、条款标题、原文摘录。
  4. 必备条款完整性：按合同类型清单查缺失/过于简略条款，缺失发现附库内示范文本（若有）。
  5. 跨条款一致性至少覆盖：主体名称（含签章/开户行）；金额勾稽（分项与总价、大小写、币种税率）；时间逻辑（生效/交付/验收/付款/质保/续约倒挂）；定义术语一致；争议解决（诉裁并存、管辖唯一性）；责任限制/违约金/赔偿互相冲突；自动续约与终止矛盾。
  6. 结论与排序：先发总体结论消息：处理建议（可签署/修改后签署/重大修改后再谈）+ 数量统计 + 高风险一句话清单；再分批发发现卡（按高→中→低→提示排序、同等级按章节，统一编号）；缺失与一致性分区编号。低风险默认折叠计数，回复"展开低风险"放出。
  7. 处理建议旁固定带"辅助意见，需人工终审"。

异常

  • 部分条款审核失败：该条标"本条未完成，回复'重试 x'重审"，不阻塞整体产出。
  • 空库：按 FR-09 限制输出。

字段要求

置信度高/中/低 + 一句判定理由（命中阈值/语义相似/推断关联）

对话产出结构（固定顺序）

  1. 总体结论消息（建议分级 + 统计 + 高风险清单 + 本次配置与快照号）；
  2. 高/中风险发现卡（分批，每批 ≤5）；
  3. 缺失分区、一致性分区；
  4. 折叠的低风险/提示（按需展开）；
  5. 未覆盖声明：哪些条款类型无知识覆盖；
  6. 依据清单消息：编号 → 条目名称/ID/版本；
  7. 收尾：快捷处置提示 + "需要导出 Word/PDF 说一声"。

导出（仅按需）

  • 用户明确要求时才产出文件；导出前确认口径（全量 / 仅未解决问题）；Word/PDF 内容含处置结果列。
  • 报告绑定知识库版本快照：日后在对话中提起该报告，引用条目展示出审时版本，并提示条目后续是否更新、可对比。
  • 重新审核生成新任务新结果，不静默覆盖历史消息中的旧结果。

处理规则

  1. 智能体先回执复述理解（"已记录：发现 3 驳回，原因 X"），更新发现处置状态；记录反馈本身不改知识库。

FR-09冷启动与空库对话P0
  • 首次对话引导：智能体主动发一条欢迎消息，用 3 个可点击/可回复的步骤引导：①发一份审核原则；②发 1～2 个典型案例；③可随时发一份合同试审。每步可跳过，用户说"怎么用"可随时重现引导。

11共享规则与异常

11.1 风险等级定义（全产品唯一定义）

等级定义典型情形对话处置导向
高可能导致重大经济损失、重大法律责任或合同核心目的落空；触碰原则层红线无限连带责任、畸高违约金无上限、核心义务无约束、管辖落空、排他锁死进总体结论高风险清单，建议必须修改
中权利义务明显失衡或显著增加我方成本，可谈判修正付款条件苛刻、验收标准模糊、责任限制单向、知识产权归属不利正常发卡，建议谈判修改
低表述不严谨、次要不利或隐患，不影响主要权利义务保密期限缺失、通知地址不全、定义不规范标准模式折叠计数，按需展开
提示非风险定性：待确认、知识未覆盖、客观提醒空白待填、无覆盖、要素疑似有误简短提示样式

11.2 置信度定义与使用

置信度判定条件展示规则
高明确命中规则判定条件（阈值计算命中、关键模式匹配）正常风险卡
中语义高度相似但表述有差异；或仅案例佐证正常发卡，措辞保留不确定性
低推断性关联、跨类型类比宽松/标准折叠为提示；严格模式放出并显著标注"需重点人工复核"
等级 × 置信度正交风险等级回答"有多严重"，置信度回答"有多确定"；低置信发现只可折叠不可删除，严格模式全部可见。

11.3 依据与溯源规则

  • 条款风险发现必须关联 ≥1 条已生效条目；缺失/一致性发现可关联系统检查项（有规则者优先）。
  • 对话中以角标编号 + 依据清单呈现；"展开依据 X"可取条目全文与来源原文摘录；条目含稳定 ID + 版本号。
  • 已停用条目不参与新审核；历史审核结果通过快照仍可查看其出审版本。
  • 建议文本必须来自规则/案例记载或其改写；智能体自行润色部分与库内文本在消息中可区分。

11.4 去重与冲突的统一规则

  • 去重触发于候选 vs 候选、候选 vs 已生效；相似只作提示，合并由用户决定，不自动删除。
  • 冲突要件：条款类型相同 + 立场相同 + 判定结论/阈值互斥。冲突未解前相关候选不生效；挑战已生效规则的修订在裁决前不生效，旧规则继续有效。
  • 裁决留痕：裁决人、时间、被取代条目、理由；原则优先级只作推荐。

11.5 会话与记忆规则

  • 知识库与默认审核配置跨会话持久；单次审核上下文（当前合同、发现编号）仅在所属会话有效，历史会话可通过搜索/引用找回。
  • 每次新审核开始时复述本次口径；长流程中存在待办（待确认候选、进行中任务）时，新会话首条消息智能体提醒一次。
  • 用户可指令"忘掉刚才的合同"清除会话内审核上下文（不删知识库）。

11.6 操作留痕与撤销

  • 知识条目确认/修订/停用/回滚/裁决、素材删除、审核任务与导出、反馈沉淀均记录：操作人（会话用户）、时间、前后值摘要；通过对话可查（FR-03）。
  • 撤销窗口：知识类操作在回执后 10 分钟内或该条目未被后续审核引用前（以先到为准）可回复"撤销"一键回退；超窗口走版本回滚。具体时长 TBD · Q7。
  • P0 不设角色权限：对话使用者拥有全部操作权并留痕；多人/分权为 P1。

11.7 数据与合规

  • 合同与素材为敏感商业数据；默认承诺用户内容不用于公共模型训练、数据租户隔离；私有化/专有模型选项见 Q1。
  • 对话回复与导出报告固定声明"本意见为智能辅助，不构成正式法律意见，最终以贵方法务/执业律师判断为准"；措辞法务审核 TBD · Q6。
  • 素材可对话删除（关联条目标记来源缺失并提示补来源，条目不自动删除）；删除素材属高影响操作需确认并入留痕。

13术语表

术语定义
对话会话用户与智能体的一次持续对话上下文；知识库跨会话持久，审核上下文随会话留存。
审核原则企业合同风险偏好与立场总纲，构成原则层。
规则条目按条款类型沉淀的可执行审核标准，含判定条件、等级与修改建议，审核主依据。
案例条目真实条款/合同片段及点评与处理方式，用于语义比对与佐证。
知识候选卡片智能体在对话中发出的结构化待确认消息；经用户确认后条目才生效。
发现卡片审核结果在对话中的结构化消息，统一编号供口头引用处置。
冲突待裁决同立场同类型条目判定互斥时的锁定状态，裁决前不得生效。
知识库版本快照审核发起时全部生效条目及版本的只读记录，用于结果复现。
严格度控制发现展示范围（宽松/标准/严格）的口头配置，不改变风险等级。
红线原则层标记的不可接受事项，命中即高风险并进总体结论清单。
