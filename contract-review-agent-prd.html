合同审核智能体 产品需求文档

把法务的审核原则与案例沉淀为可进化的知识库，让智能体依据知识库审核新合同
文档版本：v1.0（草案） 日期：2026-10-11 状态：待评审 文档类型：新产品 PRD（重型）

1背景与问题

Evidence → affected user & moment → product decision → observable outcome

观察到的问题：企业合同审核高度依赖法务个人经验——审核原则散落在指引文档、聊天记录和老法务的脑子里；历史合同的审核案例（含修订痕迹与点评）难以复用；新人审合同尺度不一、漏审高发；面对几十页合同逐条排查成本高、效率低。通用大模型虽能"看"合同，但其意见没有企业立场、不引用企业内部标准、无法持续积累组织经验，且存在无依据编造风险，难以在真实审核场景中被信任。

受影响的用户与时刻：法务/合同审核人员在两类时刻最痛：①拿到新合同（或单个争议条款）需要快速给出有依据的审核意见时；②想把自己的审核经验与历史案例传承给团队、沉淀为组织资产时。

产品决策：构建一个合同审核智能体，用户可便捷投喂审核原则与审核案例（单条款或整篇合同），智能体将其提炼为结构化、可溯源、经人工确认生效的知识库；审核新合同时，智能体仅依据知识库进行条款比对、风险定位与修改建议输出，并将用户对审核结果的反馈回流为新知识，形成"投喂—沉淀—审核—反馈"的双闭环。

预期可观察结果 ①用户上传原则/案例后，能看到结构化的知识条目候选，确认后即在库中可检索、可被审核引用；②审核新合同时，每一条风险意见都能点开看到所依据的内部规则/案例出处；③审核报告中的误报、漏报反馈可再次沉淀为知识，知识库随使用持续变厚、审核命中率随使用持续提高（指标口径见 §11 开放问题）。

2产品目标与非目标

2.1 产品目标

目标可观察的产品表现
经验可沉淀原则与案例（条款级/合同级）经解析、提炼、人工确认三步即可成为生效知识条目，沉淀过程无需用户理解任何技术概念。
知识可进化知识条目支持版本更新、停用、冲突裁决；审核反馈可生成知识更新候选；每次变更保留来源与版本链。
审核有依据单条款与整篇合同审核输出的每一条风险发现，均至少引用一条生效知识条目（规则或案例）；无依据的内容只能以"待确认提示"形式出现，不得冒充风险结论。
尺度可配置审核前可设定我方立场（甲方/乙方）、合同类型与严格度，同一合同在不同立场下输出不同意见。
结论可信任风险分级、置信度、依据跳转、缺失/未覆盖显式声明、人工终审提示贯穿全部输出；报告永久绑定出审时的知识库版本快照。

2.2 非目标（P0 明确不做）

  • 不做无人值守的自动决策：智能体不出具最终法律意见、不自动拒签/放行合同；所有风险结论为辅助意见，需人工终审。
  • 不做黑盒模型再训练：用户素材不通过不可见的"模型微调"消化；所有可用于审核的知识必须以人可读、可编辑、可停用的条目形式存在并经确认生效。
  • 不做合同起草/排版/签署：P0 仅提供条款级修改建议文本（可复制/替换），不做整篇合同起草、在线编辑、电子签。
  • 不做外部法规自动更新库：法律法规、司法解释等外部权威来源的自动订阅与更新列入 P1；P0 外部法规只能由用户作为"素材"自行投喂。
  • 不做审批流替代：不内置多级法务审批/用印流程（P1 视集成情况评估）。

3用户与核心场景

3.1 目标用户

主要用户 · 企业法务 / 合同管理员 经验沉淀者 & 审核执行者

负责公司各类合同审核，手头有审核指引、历史合同修订版和自己总结的套路。需要把经验结构化沉淀，并对业务部门提交的新合同快速出意见。

次要用户 · 业务经办（采购/销售/BD） 前置自查者

在合同法务终审前，用智能体对单个条款或合同初稿做前置自查，提前消灭明显问题。只使用审核能力，不管理知识库。

次要用户 · 法务负责人 / 外部律师 标准制定者 & 复核者

制定审核原则与风险偏好，裁决规则冲突，复核高风险合同，关注知识库质量与审核口径一致性。

3.2 核心场景

场景触发用户要完成的事完成证据
S1拿到一份审核指引文档 / 一批历史合同修订稿把原则和案例投喂给智能体并沉淀为知识素材对应的知识条目状态为"已生效"，可检索、可溯源到原文
S2业务群里发来一句争议条款（如违约责任条款）快速判断该条款在我方立场下的风险并拿到修改示范得到带风险等级、依据与替代表述的单条款审核卡
S3收到对方发来的整篇合同（Word/PDF）全面排查风险、缺失条款与前后矛盾，形成可发出的审核意见得到整篇审核报告：总体结论 + 逐条发现 + 缺失/一致性问题，可导出
S4发现智能体误报或漏报纠正本次结果，并让智能体"下次记住"反馈被采纳为知识更新候选并经确认入库，同类条款再审时口径改变

4产品定位与核心机制

智能体 = 三层知识库 + 人在回路的知识沉淀 + 依据可溯源的合同审核

4.1 三层知识模型

知识库不是一个"文档堆"，而是由三层结构化知识构成。审核时三层协同：原则层定立场与裁决优先级，规则层做结构化判定，案例层做语义比对与佐证。

第一层原则层 · Principle

审核立场与总纲。例："我方作为供货方，不接受无限连带责任""违约金不超过合同总额 20%""争议管辖优先约定我方所在地法院"。来源：公司审核指引、风险偏好文件。作用：立场过滤、规则冲突时的裁决依据、规则未覆盖时的兜底参照。

▲ 约束 / 裁决
第二层规则层 · Rule（审核主力）

按条款类型沉淀的可执行审核标准：适用合同类型、适用立场、风险点、判定条件（可含量化阈值与正反模式）、风险等级、建议修改文本。每条规则带稳定 ID、版本与来源。审核时优先进行结构化判定。

▲ 支撑 / 佐证
第三层案例层 · Case

真实的问题条款（反例）、优质条款（正例）、整篇历史合同及专家点评/修订记录。审核时对表述各异的新条款做语义相似度匹配，提供"历史上怎么判、怎么改"的实例佐证，也是生成修改示范的素材。

4.2 核心机制一：人在回路（Human-in-the-loop）的知识沉淀

智能体对投喂素材做解析与提炼，产出知识条目候选；候选必须经用户确认/编辑后才能"生效"参与审核。系统永不自动生效规则、永不因投喂直接改写已生效规则。这是法律场景下产品可信的底线机制。

4.3 核心机制二：双闭环

闭环 A · 学习闭环（素材 → 知识库）

1投喂素材原则 / 条款案例 / 整篇合同案例，粘贴或上传文件
→
2解析切分识别条款结构、归类条款类型、抽取元信息
→
3提炼候选生成结构化知识条目卡片，自动去重/标冲突
→
4人工确认编辑 / 通过 / 合并 / 裁决冲突
→
5生效入库可检索、可引用，带来源与版本

闭环 B · 审核闭环（新合同 → 反馈 → 回流知识库）

1提交合同单条款或整篇，设定立场与严格度
→
2检索比对规则结构化判定 + 案例语义匹配 + 原则立场约束
→
3审核报告风险分级、依据引用、修改建议、置信度
→
4人工处置采纳 / 驳回 / 编辑建议 / 补报漏项
→
5反馈回流生成知识更新候选，确认后回到闭环 A
为什么不直接"喂给大模型让它自己学" 黑盒学习无法回答"这条意见依据的是哪条公司标准"，无法停用一条错误经验，也无法保证立场一致。本产品的"学习"= 可审计的知识资产积累：智能体负责提炼与匹配，人负责确认与裁决；模型能力可以替换升级，知识库始终归用户所有。

5范围（P0 / P1）

P0 最小完整旅程：用户从空库起步 → 投喂至少 1 份原则与 1 个案例并确认入库 → 用该知识库审核一份单条款与一份整篇合同 → 对报告处置并把 1 条反馈沉淀回库。旅程的每一步失败都有恢复路径（解析失败可重试、提炼不准可手改、审错了可驳回回流）。

6核心对象模型与状态

所有角色、对象、状态在本文档中保持唯一定义

6.1 核心对象

对象定义关键字段（产品视角）
素材
SourceMaterial		用户投喂的原始学习材料及其解析结果素材类型（原则/条款案例/合同案例）、原文文件或文本、立场、合同类型、标签、解析切分结果、处理状态、上传人、时间
知识条目
KnowledgeItem		知识库中可被审核引用的最小生效单元，分三类：原则条目 / 规则条目 / 案例条目见 6.2 字段规范；统一含：条目 ID、类别、状态、版本号、来源引用、适用立场、适用合同类型、标签、确认人、生效时间
审核配置
ReviewProfile		一次审核所使用的立场与口径参数我方立场（甲方/乙方）、合同类型、严格度（宽松/标准/严格）、适用条目范围（全部/按标签）
审核任务
ReviewTask		一次审核动作（单条款 CLAUSE / 整篇 CONTRACT）输入内容、审核配置、知识库版本快照号、任务状态、创建人、时间、关联报告
发现
Finding		审核产出的单条意见（风险/缺失/一致性问题/提示）见 §9.1 字段规范：定位、类别、等级、说明、依据引用、建议文本、置信度、处置状态
反馈
Feedback		用户对发现的处置与纠错记录类型（误报驳回/漏报补报/建议被改/结论不认可）、原因说明、关联发现、生成的知识候选、状态

6.2 知识条目字段规范

规则条目（示例结构）审核主依据
条目名称逾期付款违约金上限审查
条款类型违约责任（可多选标签：付款、违约金）
适用合同类型买卖合同 / 服务合同 / 通用
适用立场甲方（付款方）/ 乙方（收款方）分别可配判定标准；或"双方通用"
风险点违约金比例/日费率过高，超出司法支持上限，加重我方违约成本
判定条件识别日费率/比例并年化换算；年化 > 同期 LPR 4 倍 或 总额超合同金额 20% 判为高风险；支持"包含/不包含关键词模式"与阈值表达式（阈值由用户填写，系统不臆造数值）
风险等级高 / 中 / 低 / 提示（默认值，审核时可因上下文调整）
正例 / 反例正例："违约金按日万分之五，总额不超过合同总价 10%"；反例：原文摘录
建议修改文本"乙方逾期付款的，按逾期金额日万分之三支付违约金，累计不超过应付金额的 10%。"
来源引用素材《XX 公司合同审核指引 v3》第 4.2 节；案例条目 3 条（可展开）
状态 / 版本已生效 · v2（v1 已归档，可查看差异、可回滚）

原则条目结构较简：原则表述、适用立场、优先级（冲突裁决用）、来源；案例条目结构为：条款原文（或整篇合同+定位）、条款类型、正/反例性质、专家点评、当时处理方式/修改示范、来源素材。

解析中→失败 解析失败（可重试/删除） ｜ 待确认→全部驳回 已忽略（素材留档）

候选→人工确认 已生效→编辑修订 已生效 vN+1
（旧版本归档，可回滚）
候选/已生效→与现有条目矛盾 冲突待裁决→选定为准 已生效 ｜ 已生效→停用 已停用（可重新启用；历史报告仍可溯源）

审核任务与发现状态

审核中→ 待复核→用户完成处置 已完成 ｜失败→ 审核失败（可重试，不扣次数之外无其他惩罚）
待处理→ 已采纳 ｜已知悉接受风险 ｜已驳回（误报，必填原因→回流） ｜已按建议修改

7核心用户流程

7.1 流程一：素材入库学习闭环

1添加素材选择类型：原则/条款案例/整篇合同案例；粘贴或上传
→
2确认解析结果核对条款切分与自动归类，拖拽边界、改类型
→
3审阅候选卡片逐张查看提炼结果；疑似重复/冲突有显著标记
→
4确认入库通过/编辑后通过/合并/驳回；冲突须裁决
→
5生效可引用进入知识库列表，立即可被审核检索
  • 原则素材：提炼为 1～N 张原则条目候选（一条原则一张卡）。
  • 条款案例：用户可同时给出"条款原文 + 点评/修改示范"，提炼为案例条目；若点评中包含可复用标准，额外生成规则条目候选并互相建立关联。
  • 整篇合同案例：先切分条款；有审核意见/修订痕迹的，按意见定位将"问题条款 + 意见"配成案例条目对；无意见的，仅作为语义比对案例入库，不生成风险结论。

7.2 流程二：单条款审核

1粘贴条款可附合同类型与相关上下文；条款类型自动识别可改
→
2选立场/严格度或直接沿用默认配置
→
3即时审核规则判定+案例匹配，流式给出审核卡
→
4追问/处置可多轮追问；可采纳、复制建议、驳回
→
5存为报告可选：保存为简版审核记录或导出

7.3 流程三：整篇合同审核

1上传合同Word/PDF；抽取主体、金额、期限等元信息供确认
→
2确认配置立场、合同类型、严格度、规则范围
→
3全面审核逐条审 + 完整性检查 + 跨条款一致性检查，进度可见
→
4阅读报告总体结论先行，高风险置顶，依据可跳转
→
5处置导出逐条采纳/驳回/改建议，导出 Word/PDF，反馈回流
整篇审核的三类发现来源不同，报告中分区呈现 ①条款风险发现——必须有知识库依据；②必备条款缺失——依据知识库中标记为"必备条款"的规则清单（清单是否内置见开放问题 Q2）；③跨条款一致性问题——属系统解析能力（主体名称、金额勾稽、日期逻辑、术语一致、争议方式冲突等），不需要知识库依据，但同样以"发现"形式列出、允许驳回。

7.4 流程四：反馈再学习闭环

1用户纠错驳回误报（填原因）/ 补报漏报 / 编辑建议文本
→
2生成学习候选系统聚合反馈：新规则候选或现规则修订候选，附本次条款作案例
→
3人工确认同 FR-02：可编辑、合并、裁决冲突
→
4知识库更新新版本生效，旧版本归档
→
5口径改变后续同类审核按新知识判定
↺ 高频出现的同类驳回，系统主动提示"是否将该模式沉淀为规则修订"，但同样不自动生效

8功能需求

本节为文档主体。每个模块按目的、触发、处理规则、结果与状态变更、异常组织。

FR-01素材接入与解析P0

目的：让用户以最低成本把原则与案例（条款级/合同级）交给智能体，并得到可核对的结构化解析结果。

触发与入口

  • 知识库页"添加素材"按钮；单条素材入口支持粘贴文本，文件入口支持 .docx / .pdf / .txt（P0）。
  • 审核报告内"将本条款及处置存为案例"入口（走反馈闭环，见 FR-08）。

处理规则

  1. 投喂时必填：素材类型（审核原则 / 条款案例 / 整篇合同案例）；案例类必填立场（甲方/乙方/中性）。选填：合同类型、标签、说明。
  2. 系统对整篇材料执行：正文提取 → 章节/条款切分（识别"第 X 条""1.1"等编号与标题）→ 条款类型自动归类（付款、交付验收、违约责任、保密、知识产权、不可抗力、争议解决、终止解除、责任限制、转让、自动续约等，类型清单可由用户扩展）。
  3. 整篇合同案例允许用户一并提供审核意见/修订说明（文本或修订版文件）；系统尝试将意见定位到对应条款段落，定位不准时由用户拖拽配对。
  4. 解析结果以"原文 + 切分边界 + 归类标签"预览呈现，用户可：合并/拆分段落、调整边界、修改条款类型。用户修正后的切分结果作为提炼输入。
  5. 单文件大小、篇幅上限及超限处理策略 TBD（P0 至少支持 50 页以内合同；超长合同提示分批）。

结果与状态变更

素材生成记录并进入状态机（§6.3）：已上传 → 解析中 → 待提炼（成功）或解析失败。解析成功后进入 FR-02。

异常与边界

情形产品行为
加密/损坏文件、格式无法识别明确提示原因，不计入有效素材；允许重新上传
扫描版 PDF / 图片型文件（无文字层）P0 提示"暂不支持扫描件，OCR 能力规划中（P1）"，不得用乱码内容继续提炼
切分或归类明显错误全部可手工修正；自动归类结果以"建议"样式呈现，不假装确定
重复上传同一文件按文件特征提示"疑似重复素材"，由用户决定是否继续
FR-02知识提炼与确认入库P0

目的：把非结构化素材转成三层知识条目，并通过人工确认保证每条生效知识可信、可改、可停用。

触发

素材解析完成（FR-01）或反馈生成学习候选（FR-08）后自动进入。

处理规则

  1. 系统按素材类型提炼候选卡片：原则→原则条目；案例→案例条目（并可从点评中追加规则条目候选）；审核指引→规则条目候选。候选字段遵循 §6.2 结构，字段缺失时留空标注"待补充"，不得编造数值阈值或来源。
  2. 每张候选卡展示来源锚点：可展开查看素材原文对应段落。
  3. 去重：候选与已生效/候选条目语义相似度高时标"疑似重复"，并排展示差异，提供"合并"操作；合并后保留全部来源锚点与正反例。
  4. 冲突检测：同一条款类型 + 同一立场下，判定条件互相矛盾（如阈值相反、立场结论相反）时标记"冲突待裁决"，冲突条目不允许直接生效；用户选择以哪条为准后，被取代条目转为"已停用（被取代）"并保留版本链；原则层条目可设优先级作为裁决参考。
  5. 用户对每张卡可：通过、编辑后通过、合并、驳回（留痕）。允许批量通过无冲突候选，但冲突卡必须逐张裁决。

结果与状态变更

通过的条目：候选 → 已生效（v1），立即进入检索与审核引用范围；素材状态在其全部候选处置完成后变为"已入库"或"已忽略"。每条生效条目必须完整保留：确认人、确认时间、来源素材与原文锚点。

硬性信任规则 ①候选不自动生效；②生效条目的判定标准不因新投喂被静默改写，一切修订产生新版本；③系统生成内容与用户填写内容在编辑界面视觉可区分（如 AI 生成字段有标记），确认责任归用户。
FR-03知识库治理P0

目的：让用户始终掌握"智能体到底知道什么"，并可随时纠错、停用、追溯。

功能规则

  • 检索浏览：支持关键词与语义自然语言搜索；可按知识类别（原则/规则/案例）、条款类型、合同类型、立场、风险等级、标签、状态组合过滤。
  • 条目详情：完整字段、来源锚点（点击跳转素材原文位置）、版本历史（版本间字段级差异对比）、近 90 天被审核引用次数与关联报告入口、关联反馈记录。
  • 编辑与版本：编辑已生效条目保存为新版本（vN+1），旧版本归档、可查看、可一键回滚；修改"判定条件/立场/风险等级"时二次确认并要求填写变更说明。
  • 停用/启用：停用后不参与新审核，但历史报告通过版本快照仍可展示其内容；停用需填写原因。
  • 覆盖统计（P0）：按条款类型展示各类条目数量与正反例数量，帮助发现知识盲区；命中率/误报率等质量看板列入 P1。
  • 导出：P0 支持知识库条目导出为结构化文件（CSV/Excel），保障资产可携带。
FR-04审核配置P0

目的：同一合同在不同立场与口径下输出不同、可预期的审核意见。

配置项取值与行为
我方立场甲方 / 乙方。审核仅匹配与该立场一致及"双方通用"的规则；案例按立场相关性排序。必选。
合同类型系统按文本自动推荐（附置信提示），用户可改；用于过滤适用规则与选择必备条款清单。
严格度宽松：仅展示高风险 + 高置信中风险；标准（默认）：高/中风险及以上展示，低风险折叠；严格：高/中/低全量展示，含低置信发现（显著标注）。仅影响展示与提示策略，不改变风险等级本身。
规则适用范围全部已生效条目（默认）/ 仅选定标签或条款类型范围。
默认配置用户可保存一套默认配置；每次审核仍可临时修改。
FR-05单条款审核P0

目的：对争议中的单个条款秒级给出有依据的立场化意见。

输入

  • 必填：条款文本。选填：条款类型（默认自动识别，可改）、合同类型、相关上下文条款（粘贴 1～N 段，辅助判定勾稽关系）。

处理规则

  1. 条款类型识别 → 在审核配置范围内检索：先做规则条目结构化判定（关键词模式 + 阈值换算与比较），再做案例条目语义相似度匹配与原则层兜底。
  2. 每条命中输出一条发现，字段遵循 §9.1；阈值类规则展示计算过程（如"日千分之一 ≈ 年化 36.5%，超 LPR 4 倍上限"）。
  3. 无规则命中但有相似案例时，以案例佐证出意见，置信度不高于"中"。
  4. 未覆盖处理：无任何生效知识相关时，不出具风险结论；仅输出该条款的客观解读与"知识库未覆盖该类风险，建议人工判断"声明，并提供"一键投喂为案例"入口。
  5. 多轮追问：用户可追问（如"换成乙方立场呢""如果对方不接受改法，让步底线是什么"）。追问回答同样受依据约束——无依据时显式说明，不得编造企业标准；追问中产生的有效结论可一键存为反馈/案例。

结果

输出单条款审核卡（示例见 §9.2）：条款解读 → 发现列表（等级排序）→ 未覆盖/提示区 → 建议修改文本（可复制）。可保存为审核记录。

FR-06整篇合同审核P0

目的：对整篇合同做全面、有顺序、可汇总的风险排查，产出可直接对内/对外使用的审核报告。

处理规则

  1. 解析与元信息抽取：切分条款并抽取合同主体（各方名称）、合同类型、金额与币种、关键期限（签署/生效/交付/付款/质保/到期）、签署日期；抽取结果在审核前页面请用户确认，错误可改。
  2. 逐条款审核：对每个条款执行 FR-05 同等判定逻辑；发现携带章节号、条款标题与原文摘录定位。
  3. 必备条款完整性检查：按合同类型对应的必备条款清单，检查缺失或过于简略（低于可审阈值）的条款，输出"缺失类发现"并附知识库中该类条款的标准示范文本（若有）。
  4. 跨条款一致性检查：至少覆盖：
    • 主体名称全文是否统一（与签章主体、开户行信息是否一致）；
    • 金额勾稽：分项金额之和与总价、大小写金额、币种、税率口径；
    • 时间逻辑：生效、交付、验收、付款节点、质保期、到期/续约日期是否存在矛盾或倒挂；
    • 定义术语前后一致（如"工作日/日""保密期限"定义与使用）；
    • 争议解决：诉讼与仲裁是否同时约定、管辖法院是否唯一明确；
    • 责任限制、违约金、赔偿条款之间是否互相冲突；自动续约与终止条款是否矛盾。
  5. 排序与汇总：发现按风险等级（高→中→低→提示）排序，同等级按章节顺序；高风险进入报告摘要；系统生成总体风险态势与处理建议（见下）。
  6. 处理建议分级（辅助）：可签署 / 建议修改后签署 / 建议重大修改后再谈。判定依据为发现的等级分布与是否存在"红线类高风险"（红线由原则层条目标记）。建议旁固定展示"辅助意见，需人工终审"。
  7. 长合同审核分批流式输出：已完成条款先展示，整体进度（已审条款/总条款）可见；用户可中途取消，已完成部分保留为草稿。

异常与边界

  • 解析失败/扫描件：同 FR-01 异常处理，不进入审核。
  • 部分条款审核超时或失败：该条款标记"审核未完成，可重试"，不阻塞其余条款与报告生成。
  • 知识库为空：按 FR-09 限制输出。
FR-07审核报告P0

目的：承载审核结论、依据与处置过程；可导出、可复现、可审计。

报告结构（固定分区）

  1. 报告头：合同名称、各方主体、合同类型、我方立场、严格度、审核时间、审核人、知识库版本快照号与适用条目范围。
  2. 总体结论：处理建议分级 + 高/中/低/提示数量统计 + 高风险清单（一句话标题 + 章节定位）。
  3. 逐条风险发现：按排序规则呈现，每条可展开依据与建议。
  4. 必备条款缺失：独立分区。
  5. 跨条款一致性问题：独立分区，标注涉及的两个或多个章节。
  6. 未覆盖声明：列出因知识库无相关条目而未作风险判定的条款类型，提醒人工复核。
  7. 附录：本报告引用的全部知识条目清单（名称、ID、版本）。

处置操作（在线）

每条发现可：采纳、已知悉接受风险（需选填理由）、驳回（误报，必填原因）、按建议修改（可编辑建议文本后确认）；跳转依据条目详情；复制建议文本。所有处置写入发现状态并汇总进反馈（FR-08）。

导出与留痕

  • 支持导出 Word（.docx）与 PDF；导出内容包含处置结果列（可选择"仅未解决问题"视图导出对外版本）。
  • 报告永久绑定知识库版本快照：日后打开报告，引用条目展示出审时的版本内容，并提示该条目后续是否更新（可对比新旧版本）。
  • 报告不可静默重算：重新审核生成新报告，不覆盖旧报告。
FR-08反馈与持续学习P0

目的：把每次审核中的人工纠错转化为知识库资产，让智能体"越用越懂公司口径"。

反馈类型与采集

类型采集方式必填内容
误报驳回发现上点"驳回"驳回原因（选择常见原因 + 自由说明）
漏报补报报告页"添加风险"：选中条款、手工填写风险说明与建议风险点、建议修改文本（或"仅需提示"）
建议被修正用户编辑了系统建议文本后确认"按修改后建议处理"修改后文本（系统自动留存前后版本）
结论不认可对风险等级/判定结论点"不认可"期望的等级或结论与理由

处理规则

  1. 报告完成时（或用户主动点"沉淀本次反馈"），系统将反馈聚合为学习候选：漏报/修正 → 新规则条目或案例条目候选；驳回 → 现规则条目的修订候选（调整判定条件/缩小适用范围）或反例案例候选；并自动附带本次合同条款片段作为案例素材（合同名称等敏感字段可脱敏，脱敏规则见开放问题 Q5）。
  2. 学习候选进入 FR-02 同一套确认/去重/冲突裁决流程，人工确认后才生效。
  3. 同一条规则被不同合同反复驳回（频次阈值可配）时，在该规则详情页与知识库首页提示"近期误报集中，建议复核"，但不自动改动。
  4. 用户可查看单条知识条目"因反馈而更新"的完整脉络。
FR-09冷启动与空库P0
  • 首次引导（3 步）：①上传/粘贴 1 份审核原则；②上传 1～2 个典型案例（条款或历史合同）；③用一份示例合同试审并查看依据跳转。每步可跳过，引导可随时重新打开。
  • 空库审核限制（关键）：无任何已生效条目时，整篇审核仅提供：条款切分与元信息抽取、必备条款缺失提示（若有内置清单，见 Q2）、跨条款一致性检查；报告以醒目样式声明"当前知识库为空，以下内容不含企业风险判定"。系统不得在无知识库依据时输出风险定论或修改口径，避免用户误以为通用大模型意见即公司标准。
  • 部分覆盖：某条款类型无知识覆盖时按 FR-05"未覆盖处理"执行，并在报告"未覆盖声明"分区汇总。
  • 是否提供官方/行业内置规则模板包帮助冷启动：TBD · Q2。

10共享规则与异常

10.1 风险等级定义（全产品唯一定义）

等级定义典型情形默认处置导向
高可能导致重大经济损失、重大法律责任或合同核心目的落空；触碰原则层红线无限连带责任、畸高违约金无上限、核心义务无约束、争议管辖完全落空、排他/独家锁死原则上必须修改，进报告摘要
中权利义务明显失衡或显著增加我方成本/风险，但可通过谈判修正付款条件苛刻、验收标准模糊、责任限制单向、知识产权归属不利应当谈判修改
低表述不严谨、次要不利或存在隐患，不影响主要权利义务保密期限缺失、通知地址不全、定义不规范建议优化，标准模式下折叠
提示非风险定性：待确认事项、知识库未覆盖声明、客观信息提醒空白待填项、无知识覆盖、元信息疑似有误供人工知悉

10.2 置信度定义与使用

置信度判定条件展示规则
高条款表述明确命中规则判定条件（含阈值计算命中、关键模式匹配）正常展示为风险发现
中语义高度相似但表述有差异；或仅案例佐证、无直接规则正常展示，措辞保留不确定性
低推断性关联、跨类型类比宽松/标准模式默认折叠为提示；严格模式展开并显著标注"需重点人工复核"
等级 × 置信度正交风险等级回答"有多严重"，置信度回答"有多确定"，两者互不替代；任何等级都可能低置信，任何低置信发现都不得被删除（只可折叠），保证严格模式下无隐匿。

10.3 依据与溯源规则

  • 每条条款风险发现必须关联 ≥1 条已生效知识条目；缺失/一致性发现可关联系统检查项（附规则者优先）。
  • 引用展示：条目名称 + ID + 版本号；点击打开条目详情并高亮来源锚点。
  • 已停用条目不参与新审核；历史报告通过快照仍可查看其出审时版本。
  • 建议修改文本必须来自规则/案例记载或其改写；系统自行发挥的润色部分与"库内建议文本"视觉可区分。

10.4 去重与冲突的统一规则

  • 去重触发：候选 vs 候选、候选 vs 已生效；相似度仅作提示，合并由用户决定，不自动删除任何条目。
  • 冲突要件：条款类型相同 + 立场相同 + 判定结论/阈值互斥。冲突未解前，相关条目均不得生效（已生效的被新修订挑战时，新修订不生效，旧规则继续有效直至裁决完成）。
  • 裁决留痕：记录裁决人、时间、被取代条目 ID 与理由；原则层优先级可作为系统推荐裁决顺序，但不替用户决定。

10.6 审计、数据与合规

  • 审计日志：记录知识条目确认/修订/停用/回滚、冲突裁决、审核任务创建与报告完成、反馈沉淀；含操作人、时间、前后值；日志不可由普通角色删除。
  • 数据保密：合同与素材属敏感商业数据；产品默认承诺用户上传内容不用于公共模型训练，租户间数据隔离；私有化部署/专有模型选项见 Q1。
  • 免责声明：产品内与导出报告中固定声明"本意见为智能辅助，不构成正式法律意见，最终以贵方法务/执业律师判断为准"；措辞与用户协议法务审核 TBD · Q6。
  • 删除权：素材可删除（关联条目同步标记来源缺失，条目不自动删除但提示补来源）；合同与报告可由所有者删除，删除行为入审计日志。
